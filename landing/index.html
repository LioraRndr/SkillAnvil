01

能力 · Features

把 Skill 的整条流水线，
收进一个窗口

从扫描到同步，每一环都为「不弄坏你的文件」而设计。

统一扫描全部 Agent

内置 17 个主流 Coding Agent 的目录定义，启动即扫描；名单之外的 Agent，加一条自定义路径即可接入。

编码感知的 Markdown 编辑

自动识别 UTF-8、UTF-8 BOM 与 GBK；遇到未知编码或乱码特征直接拒绝写入，不让一次保存毁掉整份 SKILL.md。

内容哈希跨 Agent 同步

同步前逐字比对，相同 / 不同 / 缺失三种状态一目了然，不会悄悄覆盖你在别处改过的版本。

快照与一键回滚

每次保存自动留存快照，任何时候一键回到历史版本。大胆改，随时退。

公共注册表溯源

对照 skills.sh 追踪技能的上游来源并比对内容，分清「自己写的」与「社区同名」。全程只发送技能名称。

自带端点的流式翻译

填入你的 OpenAI 兼容或 Anthropic 原生端点，整份 SKILL.md 流式翻译。密钥只存在本机，不经任何中间服务器。

02

工作流 · Workflow

从扫描到同步，三步成钢

不需要学习成本：打开应用，技能已经在那里。

  1. 01

    扫描

    自动发现各 Agent 的技能目录，按 Agent、标签、星标归类浏览，支持全局搜索。

  2. 02

    锻造

    在内置 Markdown 编辑器里改写 SKILL.md：编码安全、标签管理、星标收藏，改坏可回滚。

  3. 03

    同步

    选一个目标 Agent 一键同步，哈希比对保证两边内容一致，差异永远先告诉你。

同步状态一览

＝相同 — 内容一致，无需动作

≠不同 — 存在差异，确认后再覆盖

○缺失 — 目标 Agent 还没有该技能

03

隐私 · Privacy

本地优先，联网透明

没有账号体系，没有后台服务。技能文件始终留在各 Agent 的原目录；标签、快照、设置与翻译密钥都保存在本机应用数据目录的 SQLite 数据库里。整个应用只有下面三种情况会发起网络请求：

场景 何时发生 发送内容与去向
检查更新 启动时与手动检查 向 GitHub Releases API 查询新版本号
溯源比对 仅当你点击「溯源」 把技能名称发送到 skills.sh，并可能从 raw.githubusercontent.com 拉取候选 SKILL.md 比对内容，不上传文件
翻译 仅当你配置端点并触发 把你选中的文档发送到你自己配置的端点

除此之外，应用不建立任何其他网络连接。

05

答疑 · FAQ

常见问题

首次打开被系统拦截怎么办？

当前版本的安装包尚未做代码签名与公证，首次打开时 macOS 可能提示「已损坏」或「无法验证开发者」，Windows 会弹出 SmartScreen，这属于未签名软件的正常现象。按 README 的步骤放行一次即可：macOS 执行 xattr -dr com.apple.quarantine /Applications/SkillAnvil.app 或在「系统设置 → 隐私与安全性」点「仍要打开」；Windows 在 SmartScreen 里选择「更多信息 → 仍要运行」。

我的技能文件会被上传吗？

不会。技能文件只在本机被读取和写入。涉及网络的仅有三个场景——检查更新、溯源比对、翻译——都不会上传技能文件内容；溯源只发送技能名称，翻译只发往你自己配置的端点。

翻译需要什么服务？

自带端点（BYO）：任何 OpenAI 兼容接口或 Anthropic 原生接口都可以，在设置里填入地址、密钥与模型后即可流式翻译整份 SKILL.md。不配置端点就不会有任何翻译请求；密钥只保存在本机数据库。

支持哪些操作系统？

macOS（Apple Silicon 与 Intel 通用 DMG）、Windows x64（EXE 安装器与 MSI）、Linux（AppImage、deb、rpm），均可在 GitHub Releases 下载。

数据都存在哪里？备份方便吗？

技能文件仍在其所属 Agent 的原目录，不会搬家；标签、快照、设置与密钥保存在系统应用数据目录下的 SQLite 数据库中，复制该文件即可完成备份。

列表里没有我用的 Agent？

在设置中添加自定义技能目录即可，扫描、编辑、标签、快照与同步等能力和内置 Agent 完全一致。
